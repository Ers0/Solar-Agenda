🧠 Guide: Training TARS with Machine Learning

This playbook explains how to transform field technician logs, resolved tickets, and inverter runbooks into a fine-tuned Machine Learning model for TARS.

Step 1: Dataset Generation & Logging

Every time a technician closes a ticket or writes a resolution note in Solar Agenda, it captures the fault symptoms, inverter model (Deye, Foxess), and real corrective steps. Click "Export Training Dataset (.JSONL)" in Settings to automatically compile these into standardized prompt-completion pairs.

Step 2: Supervised Fine-Tuning (SFT) with Google Gemini

You can fine-tune Gemini directly in Google AI Studio with zero cloud infrastructure setup:

  1. Go to Google AI Studio → Tune Models.
  2. Click Create Tuned Model and select gemini-1.5-flash or gemini-2.5-flash as base model.
  3. Upload the solar-tars-dataset.jsonl file exported from Solar Agenda.
  4. Set Epochs to 3–5, Batch size to 4, and Learning rate multiplier to 1.0.
  5. Click Tune. Once training finishes (~15-30 min), copy your fine-tuned model ID (e.g. tunedModels/solar-tars-v1) into Settings or environment secrets.

Step 3: Open-Source Local Fine-Tuning (LoRA / QLoRA)

For completely offline field laptops using Llama 3 or Mistral:

pip install unsloth "transformers[torch]"

Step 4: Continuous Reinforcement from Field Feedback

In the TARS drawer, whenever a technician marks an answer as helpful or edits a draft note, TARS records positive reinforcement weights in Learn.rules. This hybrid approach pairs fine-tuned model weights with real-time in-context memory.
